# 成长轨迹系统实施方案（缺口 1：成长型正反馈）

> 上游：`docs/正反馈设计评估.md` §四「给成长一个可见刻度」
> 状态：设计稿（未实施）
> 日期：2026-08-10

## 一、目标

为三个具体缺口提供累积型反馈：

1. **扩张时间线** —— 占了多少城、何时占的，聚合可回顾
2. **里程碑系统** —— 「收复东北」「半壁江山」式成就
3. **数值趋势图** —— 城池/兵力/士气/府库的变化曲线

核心原则：**全部建立在既有事件溯源之上，存档零新增字段**。

## 二、数据流总览

```
eventLog（既有，存档本体）
   ├── buildExpansionTimeline() 折叠 ──→ 扩张时间线（纯派生，零存储）
dateAdvance（applyEvent 分支，每回合必过）
   ├── takeTurnSnapshot()   ──→ turnSnapshots（派生态，重放自动重建）
   └── evaluateMilestones() ──→ milestonesUnlocked（派生态，重放自动重建）
                                    └─→ 新解锁时 toast（isReplaying 守卫）
以上三者 ──→ ChroniclePanel.vue「战纪」面板（三 tab + 头部统一度进度条）
```

### 关键决策：不往 SaveData 加任何字段

`relations` 已验证过这条路：不落存档、靠 eventLog 重放重建。快照与里程碑同法：

- `load()` = initWorld + 逐事件 applyEvent 重放，重放时 dateAdvance 分支照常执行 → 快照/里程碑**自动重建**，且「首达日期」天然正确
- 老存档零迁移；eventLog 保持纯净（不加新事件类型）
- 趋势数据**不能**靠开面板时从 eventLog 反推：缺粮损兵（`FAMINE_TROOP_LOSS_RATE`）在 reducer 内按比例扣、战斗士气损耗不全落事件，重放 reducer 才是精确路径——而 dateAdvance 时刻的 store 状态恰好就是精确值

## 三、新增文件（4 个）

### 1. `utils/chronicle.ts`（纯函数，可单测，~120 行）

```ts
export interface ExpansionEntry {
  date: string   // 该事件所属回合的起始日期
  gb: string
  name: string
}

/** 折叠 eventLog 得玩家扩张时间线。capture 记其所在回合的当前日期（dateAdvance 推进前的日期）。 */
export function buildExpansionTimeline(
  eventLog: GameEvent[],
  faction: Owner,
  cities: Record<string, { name: string }>,
): ExpansionEntry[]

/** GB 编码第 4-5 位为行政区划省码：'156420700' → '42'（湖北）。非法返回 null。 */
export function provinceOf(gb: string): string | null

/** 世界省份表（模块加载时从 chinaCities 静态计算一次）：省码 → { name, total } */
export const PROVINCE_TABLE: Record<string, { name: string; total: number }>

/** 玩家当前各省占有数（供里程碑谓词用） */
export function countOwnedByProvince(ownership: Record<string, Owner>, faction: Owner): Record<string, number>
```

- v1 时间线条目不含「从谁手中」（capture 事件未携带前属主，折叠时额外维护属主表不值当），只显示「日期 · 克某城」
- 开局领土不进时间线，面板以「肇基 · 开局领 N 城」作为第 0 条静态展示

### 2. `data/milestones.ts`（声明式谓词表，~180 行）

```ts
export interface MilestoneContext {
  faction: Owner
  cityCount: number
  totalCities: number                        // 世界总城数
  captures: number                           // 玩家累计占城数（store 计数器）
  provinceOwned: Record<string, number>      // 省码 → 我占城数
  troops: number
  morale: number
  treasury: number
  granary: number
}

export interface MilestoneDef {
  id: string
  title: string          // 「收复东北」
  flavor: string         // toast 副文案
  sealChar: string       // 印章单字（战纪面板印章墙用）
  tier: 1 | 2 | 3
  check: (ctx: MilestoneContext) => boolean
}

export const MILESTONES: MilestoneDef[]

/** 纯函数：返回本次新解锁的 id 列表（已解锁的跳过） */
export function evaluateMilestones(ctx: MilestoneContext, unlocked: Record<string, unknown>): string[]
```

首批里程碑（约 12 条，全部**状态谓词**，不依赖战斗过程历史）：

| tier | 里程碑 | 判定 |
|---|---|---|
| 1 | 初克一城 | captures ≥ 1 |
| 1 | 十城之基 | cityCount ≥ 开局 + 10 或 ≥ 10（以 captures≥10 替代，免存开局基数）|
| 1 | 带甲十万 | troops ≥ 100 |
| 1 | 府库充盈 | treasury ≥ 500 |
| 2 | 收复东北 | 辽(21)/吉(22)/黑(23) 全省在握 |
| 2 | 雄踞一方 | cityCount ≥ totalCities × 1/4 |
| 2 | 兵精粮足 | troops ≥ 80 且 granary ≥ 300 |
| 3 | 半壁江山 | cityCount ≥ totalCities × 1/2 |
| 3 | 三分天下有其二 | cityCount ≥ totalCities × 2/3 |
| 3 | 天下一统 | cityCount ≥ totalCities × 0.95（与 gameOver 联动呼应，不严格等于 100% 防漏）|

> 区域里程碑对「该省在世界中有城」做前置检查（`PROVINCE_TABLE`），避免种子数据缺省时误判。

## 四、既有文件改动（4 处）

### 1. `stores/game.ts`

```ts
// 新增状态（派生态，不落档）
const turnSnapshots = ref<TurnSnapshot[]>([])
const milestonesUnlocked = ref<Record<string, { date: string; turn: number }>>({})
const playerCaptures = ref(0)   // 玩家累计占城计数（重放自动重建）

interface TurnSnapshot {
  turn: number; date: string
  cityCount: number; troops: number; morale: number
  treasury: number; granary: number
}
```

三个挂钩点：

| 位置 | 改动 |
|---|---|
| `applyEvent` 的 `dateAdvance` 分支 | turnCount++ 后：`takeTurnSnapshot()` + `evaluateMilestonesForPlayer()`（两者重放期照常执行=重建；toast 仅 `!isReplaying` 时弹）|
| `applyEvent` 的 `capture` 分支 | 若 `e.actor === currentFaction.value` → `playerCaptures.value++`（重放同样重建）|
| `initWorld()` | 三者清零 |

`evaluateMilestonesForPlayer()` 流程：build ctx（用 myMilitary/factionTroops 等既有聚合）→ `evaluateMilestones(ctx, unlocked)` → 新 id 写 `milestonesUnlocked[id] = {date, turn}` → toast（icon `rosette`、tone `amber`、title `功业 · ${title}`）。

return 块暴露：`turnSnapshots`、`milestonesUnlocked`、`totalCities`（= Object.keys(cities).length）。

## 七、边界与风险

- **重放期 toast 静默**：读档重放走 dateAdvance 分支会重建快照/里程碑，toast 由 `isReplaying` 守卫，不刷屏（与 selectFaction 择势提示同模式）
- **省份种子缺省**：区域谓词先查 `PROVINCE_TABLE` 中该省 total > 0 才生效
- **多存档切换**：initWorld 清零三态，load 重建，无串档
- **性能**：快照/里程碑每回合 O(1) 增量；时间线折叠 O(eventLog) 仅在打开面板时经 computed 执行一次
- **统一度分母**：用 `Object.keys(cities).length`（380，seed 已过滤无 gb 条目），不硬编码

## 八、不做的事（v1 明确排除）

- 多势力对比曲线（只采玩家一份；未来可扩为全势力 cityCount 堆叠）
- 时间线条目的「从谁手中夺取」（capture 事件无前属主字段）
- 战斗过程类里程碑（✅ 已于 battleEnd 结算阶段落地：首胜会战 `first-major-victory` / 胜绩初成 `first-victory` / 鏖战决胜 `bloody-battle`）
- 元进度/科技树（评估文档 ⑤，长线另立）
