# 势力主动目标与反击首版

## 问题

已有 AI 会收到经济建议和 1k 合法路线示例，但没有明确区分保卫受攻城市、支援现有战线、收复近期失地和先集结再进攻。势力历史还按当前城主筛选，导致丢失城市后原城主可能看不到这次失地；结构及战略预检拒绝也可能在入队前消失，下一轮无法据此调整。

## 目标与范围

- **前线优先**：独立势力决策先看到受攻城市、已有战线、前线断供、近期失地和可达交战目标，不再只收到后方例行建设建议。
- **失败可追踪**：历史按事件发生时归属筛选，攻守损失不混称“我损/敌损”；预检拒绝生成零消耗的可信失败回执，不把未执行计划当成已执行。
- **合法建议**：候选和行动例子复用正常路线、外交、资金、行动点检查；建议不代替模型选择和整批累计校验，也不保胜。
- **真实验证**：计划用十至十五回合的真实模型、正常规则引擎验证前线响应和受挫调整。明确区分真实模型引擎测试、离线重放和浏览器实机验证，不以固定空行动敌方证明战略能力。

## 非目标

不新增敌方免费兵力或银粮，不绕过战斗、占领、补给与停战规则，不自动执行建议，不为了制造反击而强迫对无关和平势力宣战。本轮优先相关势力的独立 AI，不同时重写全国次要势力批量外交、科技树或地图交通。

## 玩家故事与验收

- **受威胁者**：当敌方城市正在被进攻，其决策目标应指向保卫该城，并只给合法调兵、征兵、筑防或整军例子。
- **失地者**：城市易主后，原城主仍能看见易主事实；若双方交战且路线合法，优先比较收复，不因城主变化而失忆。
- **观察者**：NPC 可以主动进攻可达交战目标，但应保留驻军、关注补给、预算和守军；1k 路线示例不得当作足够攻城力量。
- **复盘者**：结构/战略预检拒绝的指令会留下原因、真实势力及零消耗回执；下一轮使用现状余额调整，不复制历史余额，也不伪造执行成功。

验收包括：非交战/同盟/停战不诱导新战争，零行动点不建议付费动作，断供先提示恢复，已开战来源城不重复开战，建议无状态副作用；失地历史、重放、失败回执和明确等待理由分别测试。

## 测量与边界

记录原始规划指令数、结构/战略拒绝、执行层拒绝、实际消耗、前线相关行动、开战/失地/断供与连续空行动回合。调用失败和解析失败单独记录，不以重试后成功掩盖第一次失败；不预设未经实测的胜率或耐玩分数。真实模型长局的场景范围、控制方、其他势力策略和动画替身应在结果中明确说明。

首版实现与十四项专项自动测试已完成，验证范围和短局结果见 `faction-initiative-results.md`。计划中的完整真实模型长局未完成，不能把短样本、离线浏览器重放或分段工具测试当作完整战略对局。

## 有界复测

正常回归默认跳过联网测试。复测应使用已配置 `step-5-preview` 的可信后端，提供 `/api/ai/chat` 接口；鉴权由后端管理，不把密钥写入命令、报告或仓库。优先单场景、每段一个有效回合，报告的 `coverage.complete` 才表示目标回合数已完成。

```sh
MAPWAR_PRESSURE_URL=http://127.0.0.1:3000 \
MAPWAR_PRESSURE_CASE=defense \
MAPWAR_PRESSURE_TURNS=12 \
MAPWAR_PRESSURE_CHUNK=1 \
MAPWAR_PRESSURE_OUTPUT=/tmp/map-war-defense.json \
pnpm --dir apps/web exec vitest run tests/factionPressure.live.spec.ts --maxWorkers=1
```

继续同一场景时增加 `MAPWAR_PRESSURE_RESUME=/tmp/map-war-defense.json`，输出仍使用同一文件。恢复检查失败必须停止，不能把新开局拼接为连续长局；请求最终失败也停止在上一正常存档，不以空行动推进。反攻场景改用 `MAPWAR_PRESSURE_CASE=counterattack` 和单独报告文件。
