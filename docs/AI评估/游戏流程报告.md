## 二、核心循环：P1 → P4 四阶段回合流

```
P1 玩家阶段 → P2 调度分流 → P3 势力 AI 决策 → P4 世界结算 → loop
```

### 2.1 P1 玩家阶段

玩家通过自然语言输入指挥，例如"川军自重庆挥师东进攻杭州"。流程为：

1. `PlayerAiPanel.vue` 接收输入
2. `useAiOrchestrator('user')` 发起 LLM 调用
3. `extractPayloads` 抽取结构化指令
4. 四层校验：结构校验 → 硬编码规则 → AI 可行性裁定 → 世界校验
5. 校验通过后自动 `executeOrder` 执行 + PixiJS 动画演出
6. 玩家可反复输入，随时点「结束回合」进入后续流程

### 2.2 P2 Agent-Kernel 调度

`useAgentKernel.runWorldTurn` 中：

1. `classifyFactions()` 把势力分为 `related`（与玩家接壤/相关）和 `unrelated`（偏远小势力）
2. related → 专属 AI 实例并行决策
3. unrelated → 世界 AI 批量代打
4. 两组并行 `Promise.allSettled`

### 2.3 P3 势力 AI 决策

1. 每势力独立 LLM 调用（`invokeFactionAI`）或批量调用（`invokeWorldAIBatch`）
2. 输出解析 → 校验 → `advance()` 串行执行（动画 + `applyEvent`）
3. 电报系统在此阶段注入：AI 决策可附带 `telegram` 字段，搭车发送 direct/world 电报
4. 电报进决策上下文：`buildFactionContext` 注入近 6 条 direct；`buildSettleContext` 注入近 8 条 world

### 2.4 P4 世界结算

**P4a 战斗裁决**（`settleActiveBattles`）：
- ① 前置检查 + `computeBaseBattle` 基础公式
- ② AI 调味层（LLM 生成 narrative，失败降级）
- ③ `clampFlavor` + apply attack/morale
- ④ 终局复检（士气崩溃 > 兵力归零）

**P4b 世界 AI 结算**（`invokeWorldAISettle`）：
- 生成 narrative（叙事文案）
- 生成 chatter[]（世界公屏电报）
- 生成 newDate（推进日期）
- `playTimeJump`（云雾蒙太奇 + `dateAdvance`）
- `autoSave()` 自动存档

## 六、技术债与已知风险

### 6.1 单文件过载

| 文件 | 行数 | 问题 |
|------|------|------|
| `LeafletMap.vue` | 2842 | 地图渲染 + UI 状态 + 相机控制 + 右键菜单 + 模态框混在一起 |
| `gameOrders.ts` | 1108 | giant switch + 模块级可变状态 |
| `game.ts` | 924 | reducer + 存档 + 电报 + 派生聚合全塞在一个文件 |

### 6.2 性能热点

| 热点 | 复杂度 | 说明 |
|------|--------|------|
| `ownership` computed | O(N) 每帧 | 每次访问全量重建 `Record<string, Owner>` |
| `factionTroops(o)` / `factionMorale(o)` | O(N) 每调用 | AI 上下文每回合多次调用 |
| `buildFactionContext` | O(N) + 邻接遍历 | P3 每势力每回合调用 |
| `getSnapshot` | O(N) 深拷贝 | P2/P3 各至少调用一次 |
| `syncBattleCards` | O(B²) | 每帧碰撞检测 |

### 6.3 内存风险

| 风险点 | 现状 |
|--------|------|
| `eventLog` 无限增长 | localStorage 有 5MB 上限，无上限裁剪 |
| `telegrams` 无限增长 | 无上限 |
| `chatTurns` 无限增长 | 无上限 |
| `undoStack` 无限增长 | 无上限 |
| `battleRegistry` / `activeBattles` | 模块级 Map，异常路径可能遗漏清理 |
| `geoJsonCache` | 无限增长，无 LRU |

## 九、下一步建议（优先级排序）

1. **外交状态矩阵**（同盟/宣战/停战 + 求和谈判已部分落地，缺状态持久化）
2. **规则 AI 兜底**（LLM 失败/超时时降级）
3. **快照瘦身**（P2/P3 上下文只传必要字段，砍 O(N) 开销）
4. **势力覆灭自动判定**（`auditFactionSurvival` + 终局检查）
5. **胜利条件**（统一全国/消灭 N 势力/存活 X 天）
6. **文件拆分**（LeafletMap 2842行 / gameOrders 1108行 / game.ts 924行）
7. **补给/后勤**（调兵距离限制、占领区通行）
8. **消灭关键 as 断言** + 补核心测试 — 类型安全与重构安全网

## 十、总结

项目处于 **「设计领先、骨架扎实、内容待丰」** 的阶段。核心架构（事件溯源、Kernel 唯一写者、P1-P4 回合流、三层 AI、动画引擎、经济系统、地形修正）已经完整落地且工程质量较高；但「让游戏好玩」的核心循环——经济产出 → 扩张压力 → 外交博弈 → 胜利目标 ——尚未完全接通。

当前最优先的落地项是：外交状态矩阵（设计稿已完成、求和谈判已部分落地）、规则 AI 兜底、快照瘦身、以及势力覆灭自动判定。
