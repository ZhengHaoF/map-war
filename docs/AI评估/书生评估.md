## 1. 核心玩法循环：已通

```
玩家发令（军师面板）
    → 世界AI 解析意图 → 结构化指令 + 可行性裁定（四层校验：结构→硬编码规则→AI 可行性→世界AI）
    → 串行播放 PixiJS 动画 + 落地世界态
    → 结束玩家回合
    → 世界回合：政权分类 → 并行 LLM 决策 → 指令演出 → 战斗裁决（LLM + fallback 公式） → 世界叙事 + 推进日期
```

**评价：** 循环已端到端跑通。玩法差异化在于自然语言指挥，但**玩法深度取决于 AI 生成指令的质量**，本质上是"AI DM"游戏。

---

## 2. 游戏深度与机制

### ✅ 扎实的骨架

- **10 大政权 + 380 城**：每个政权有独立 capital、leader、strength、description，开局择势有仪式感。
- **城市态完整**：每城含 `troops`、`fieldForce`、`morale`、`industry`、`food`、`fort`、`cityLevel`、`terrain`——维度较全。
- **内政/建设系统四条线**：`recruit`、`develop`、`fortify`、`rally`，UI 飘字反馈完整。
- **战斗系统**：`deploy` → `battle`（开战，自动出兵兜底，也可指定 deployAmount）→ `reinforce`（增援）→ 每回合 P3 LLM 裁决损耗（fallback 公式兜底）→ 守方归零则 `capture`（占城）→ 攻方外出归零则溃败。
- **势力存亡**：`setFactionAlive`，覆灭 toast 提示。
- **电报系统**：AI 自主发电报，`direct`（势力私信）+ `world`（公屏），玩家可即时回信。
- **顾问AI**：场外分析→可执行建议→点击一键填入军师面板，与军师分工清晰。
- **事件日志**：只读时间流水，带类型 badge。

### ⚠️ 缺失/薄弱环节（拉低可玩性）

| 问题 | 说明 | 严重度 |
|------|------|--------|
| **地形战斗加成未硬实施** | 数据有 terrain（山地/丘陵/平原/林地），`battleFormula.ts` 现已有 `terrainFactor`（mountain 1.5x / hill 1.2x / plain 1.0x）+ `fortMaxFactor`（2.0x）直接参与计算 | ~~高~~ → **已降级** |
| **没有补给/后勤机制** | 兵力无限远程调动，无视距离、无视占领区、无视补给线——战略决策空心化 | 高 |
| **外交状态矩阵缺失** | `classifyFactions` 只有 related/unrelated 二分，无同盟/宣战/停战状态；但有电报 + 求和谈判（`peaceAi.ts`） | 高 |
| **战斗被动化** | 战斗每回合自动损耗，玩家无法手动指挥具体战术（如迂回、包围、伏击），只能下"开战/停战/增援"粗粒度指令 | 中 |
| **AI 不可控** | 所有 NPC 势力决策交给 LLM，返回"空 orders"就按兵不动，行为一致性差 | 中 |
| **世界列强未接入** | worldCountries.seed.json 有日/美/苏/英/法/德/意数据，但只在电报-normalize 中用，不参与中国战场 | 中 |
| **科技/发展无长线** | 城市 stat 有上限（industry/food/fort 100），但无科技树、无解锁、无产业升级路径 | 低 |
| **胜利条件缺失** | 代码中无"统一全国"或"达成某目标=胜利"的判定，游戏可以无限进行 | 中 |

### 🟡 半实现

- **邻接图已落地**（chinaCitiesAdjacent.ts + buildFactionContext 注入 AI），但邻接关系**只做展示**，不限制行军可达性或影响战斗。
- **自由行动路径**（freeAction）已通：玩家说"办学""通电"→ AI 叙事 + 可选 effects（cityStatChange/moraleChange/produce/moveTroops/sendTelegram），但 effects 只有 5 种复用事件，无法表达真正的开放行动（如"策反""暗杀""决堤"只能映射到已有事件或纯叙事）。

> **[2026-07-29 补充：经济系统已落地]** `economy.ts` + `economicTick` + `treasury`/`granary` + `lastEconomy` 收支拆分 + `PlayerStatusPanel` 展示。

## 3. 叙事与氛围

### 强项

- **历史感**：1931 年背景 + 1931 年历史地名映射（北平/奉天/安东/迪化/归绥）+ 政权详情大段描述，氛围框架到位。
- **羊皮纸水墨风**：全局 CSS 变量（paper/ink/cinnabar），所有 UI parchment 变体统一，在同类游戏中辨识度极高。
- **事件叙事**：P4 世界 AI 产出 narrative，eventLog 面板按时间线展示；电报 chatters 用势力口吻短评。
- **时间跳跃演出**：云雾蒙太奇（cloudTransition.ts）盖屏→改钟→揭开，视觉上将日期推进包装成"时光流逝"。

### 弱点

- **叙事碎片化**：narrative 每段独立，无跨事件长线叙事（如"九一八事变"没有专属触发链或过场）。
- **无角色/人物交互**：只有势力代号，没有将领/谋士个体，缺少人味儿。
- **UI 文案质量波动**：toast 和 battle narrative 依赖 AI 生成，风格不稳定（半文言 vs 白话混搭）。

## 4. 玩家体验

### 正面

- **自然语言门槛低**：玩家不需要知道编码或枚举，说城市名即可（locationResolver 做 name→gb 映射）。
- **视觉反馈强**：每条指令都有 PixiJS 动画（箭头弧线、雷达扫描、光球爆炸、战斗光束、占领飘字、建设飘字），镜头跟随（聚焦→跟随→归位），演出感好。
- **撤销机制**：snapshotForUndo/restoreUndo 单步快照，调试友好。
- **存档/读档稳健**：事件溯源 + shallowRef 优化，读档恢复战斗动画（restoreActiveAnimations），自动存档每回合。
- **多层校验安全感**：结构校验→战略规则→AI 可行性→执行 toast，坏指令不会静默失败。

### 负面

- **节奏慢**：每条指令串行 await 执行（含动画），批量指令一队一队播，无法倍速/跳过——长线游戏会累。
- **信息密度低**：380 城全量在 getSnapshot 里，但 UI 只展示当前选中城详情（InfoTable），没有全局战略视图。
- **无教程/引导**：择势后直接丢进地图，没有教学关卡或提示；AI 契约虽然详尽但玩家看不到。
- **BGM/音效缺失**：代码中无任何音频相关，氛围靠视觉撑。
- **调试按钮暴露**：LeafletMap 的"调试"面板对玩家可见（虽然被 isDev 守卫，但 dev 环境下是暴露的），缺少干净的生产/开发分离。

## 5. 技术架构对游戏性的反哺与制约

### 架构优势（可支撑扩展）

- **事件溯源 + Kernel 唯一写者**：状态变更可追溯、存档=序列化日志、读档=重放——这为"回看历史""回放推演"提供了天然基础。
- **指令契约与 AI 解耦**：19 条指令（gameOrders + aiOrderContract）定义清晰，AI 输出→结构化→校验→执行，管线干净。新增玩法=加指令+加 prompt。
- **动画与状态分离**：PixiJS 动画纯视觉，世界态统一 applyEvent——动画可以替换/升级不影响逻辑。
- **前后端分离合理**：后端仅 LLM 透传，所有游戏逻辑前端——延迟低，但意味着无法多人联机。

### 架构制约

- **所有 AI 编排在前端**：每回合并行 LLM 调用全部走前端 fetch——一旦回合中涉及的势力多，等待时间线性增长，且无法在服务端做缓存/批处理优化。
- **无多人能力**：权威态在 Pinia store（内存），localStorage 存档——这是单机电竞游戏架构，不支持多人联机。
- **LLM 依赖过重**：玩家指令要 AI 解析，势力决策要 AI，战斗裁决要 AI，电报回信要 AI——没有 AI 就什么都做不了，且成本与延迟不可控。

## 6. 改进建议（按优先级）

1. **加外交状态矩阵**（同盟/宣战/停战 + 求和谈判已部分落地，缺状态持久化）— 让 10 大政权真正互动
2. **加补给/兵线限制**（调兵距离限制、占领区通行）——让地理真正重要
3. **加胜利条件**（统一 / 坚守 X 年 / 关键事件链）——给游戏一个终点
4. **倍速/跳过演出**（推进动画可跳过）——长线体验瓶颈
5. **全局战略视图**（总览面板真正接入所有势力数据）——决策信息基础
6. **接入世界列强**（九一八后苏联态度、欧美反应）——把世界层从装饰变实打实的影响因子
7. **规则AI兜底**（minor势力用启发式）——降低LLM成本
8. **文件拆分**（LeafletMap 2842行 / gameOrders 1108行 / game.ts 924行）— 可维护性
9. **消灭关键 as 断言** + 补核心测试 — 类型安全与重构安全网

当前代码质量扎实、管线清晰，**缺的不是架构而是玩法内容填充**。如果能在现有骨架上补上地形/补给/外交/胜利条件，会从"AI 推演 demo"升级为真正的策略游戏。
