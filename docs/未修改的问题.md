## needsPlayerDecision 进事件层

✅ **已实施（2026-08-31 · commit `15f6204`）。** 实现比原方案更简，未拆「剩余事件暂存 + 继续回放」那套机制：

- `game.ts` 新增 `GameEvent` 类型 `{ type: 'pauseForPlayer' }`（不改世界态，仅落日志）
- `applyEvent` 对该事件直接 `return { ok: true }`，replay 严格等价
- 停点判据是**派生 computed**：`pausedForPlayer = eventLog 末尾是 pauseForPlayer`——末尾之后还有事件即视为已决策过，天然幂等；连续停点只对最新的生效
- `useGameScheduler.ts:350` 在遇到 `needsPlayerDecision` 时追加该事件
- `useSaveGame.ts` 读档时若检测到停在停点上，补一句提示避免玩家错过拍板时机

<details>
<summary>原始问题与修复方向（存档备查）</summary>

**问题**：`needsPlayerDecision`（需玩家决策的停点）只在 `GameOrder` 指令层生效，未持久化到 `eventLog`。读档回放时不会在曾需要决策的位置暂停，玩家错过决策点。

**修复方向**：
1. `game.ts`: 新增 `GameEvent` 类型 `{ type: 'pauseForPlayer' }`
2. `game.ts` `applyEvent`: 处理 `pauseForPlayer`，返回 `{ ok: true, paused: true }`
3. `game.ts` `load()`: 遇到 `paused` 事件时中断回放，暂存剩余事件，等玩家操作后继续
4. `useGameScheduler.ts`: 调度器遇到 `needsPlayerDecision` 时追加 `applyEvent({ type: 'pauseForPlayer' })` 写入日志
5. `game.ts`: 新增"继续回放"函数，玩家决策完成后回放剩余事件

# 审查中确认的设计/数据问题（暂缓项）

记录审查中确认存在但暂缓修改的设计/数据问题，供后续迭代参考。

## minor 政权批量上下文缺邻接/可达性信息

- **位置**：`utils/aiContext.ts` `buildMinorContext()`
- **现象**：世界 AI 批量代打次要势力时，上下文只给每个势力的城清单 + 兵力 + 全局历史，没有邻接城市列表
- **影响**：次要势力生成的进攻指令可能跨势力、地理不可达，被战略校验拦下，白烧 token
- **对比**：主势力 AI 的 `buildFactionContext` 已包含一阶邻接城市分组
- **暂缓原因**：次要势力本身行为保守（prompt 引导"保守为上，无大事按兵不动"），实际出现概率低；补齐邻接需按势力分组建邻接表，改动量略大
- **建议方案**：在 `buildMinorContext` 中为每个次要势力追加邻接城市（复用 `adjacentMap`），格式与 `buildFactionContext` 一致
- **现状（2026-10-09 核对）**：仍开放。`buildMinorContext` 此后只增强了 `sinceDateAdvance` 历史注入，邻接/可达性依旧缺失。彻底解决依赖邻接表数据工程（见 `项目进度评估-2026-10-09.md` 第六节 1）
