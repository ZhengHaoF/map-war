# 地图进攻／调兵选城实施与验收

## 实施范围

依据 [交互评估](https://github.com/ZhengHaoF/map-war/blob/master/docs/map-command-shortcuts-assessment.md)，实现一个不持久化的行军草稿。保留既有羊皮纸界面、下拉列表、行军预览、调度器和规则检查；不修改行军费用、外交规则、战斗公式、补给或存档结构。

- **入口**：工具栏增加“进攻”“调兵”。已有己方选中城时复用为出发城，否则先选己方出发城。选城模式自动切到市级地图；手动切图层取消草稿。
- **状态**：`idle → pickingSource → pickingTarget → reviewing`。选城只改变界面状态，没有入队、扣费、部署、宣战或推进日期。
- **地图高亮**：可选城市绿色，出发城蓝色，已选目标朱砂色。复用实际路网，排除同城、错误归属、穿越第三方、停战、同盟及已占用来源战线。高亮表示拓扑／外交可选，不保证当前兵量、预算、行动点足够，也不表示攻击安全。
- **面板回填**：一次交接行动类型、出发城、目标城。同步清理 watcher 先运行，再写目标，避免异步 watcher 擦掉地图目标。兵量默认重置为最多 1k；已有外出部队仍可使用原有 0 新增兵量选项。
- **重选与替代入口**：面板可以地图重选出发城或目标城，使用面板实际已编辑的值。选城提示提供取消与“用下拉选择”；下拉查询及不可执行原因保留。
- **执行边界**：必须在行军预览点击最终确认。预览随最新状态变化，调度器再复检。执行中禁止重复点击，成功且未编辑的同一草稿锁定确认，编辑或重新选择后解锁。
- **小屏确认**：确认和取消放在独立底栏，不随风险说明和目标列表滚出屏幕。行军面板使用明确的位置，不叠加通用弹窗的自动级联偏移；其他弹窗维持原默认行为。
- **取消**：Esc、取消按钮、关闭面板、势力变化、读档或回放清除草稿、高亮和面板。空白点击不选城，拖动超过 5px 即使回到起点也不选城。
- **快捷键**：A 进攻、M 调兵、Esc 取消。编辑控件、可编辑区域、组合输入、重复按键及 Ctrl/Meta/Alt 组合不启动选城；阻塞式弹窗、AI 请求、待执行队列、调度运行、读档回放与结束游戏不启动。

## QA 清单

验收以新增交互为范围，不以旧游戏全部功能或真实模型对局为本轮完成条件。

| 场景 | 功能检查 | 视觉证据 |
| --- | --- | --- |
| 先动作再两城 | 进攻与调兵分别回填正确两城和类型，确认前世界不变 | 桌面出发城、目标城、预览 |
| 已选己方城 | 直接进入目标选择，不残留旧目标 | 桌面目标步骤 |
| 取消／重选／列表 | 完整进入退出循环，重选使用实际面板值，列表可用 | 提示区与行军面板 |
| 非法选择 | 敌城不能作源、调兵不能选敌城、同城和断路不可选 | 原因提示 |
| 拖动／空白 | 拖动返回起点仍不误选，空白不清草稿、不执行 | 草稿状态前后比较 |
| 外交变化／余额变化 | 高亮与预览重新检查，执行仍走规则门禁 | 拒绝提示／禁用确认 |
| 快捷键与忙碌 | A/M/Esc 生效，编辑／组合／AI／待执行期间不生效 | 模式前后比较 |
| 读档／切换势力 | 草稿和幽灵高亮清理，不改变资源 | 清理后地图 |
| 防重复确认 | 执行中与成功未编辑草稿不重复入队 | 成功回执与禁用确认 |
| 窄屏 | 两个入口、当前步骤、取消与最终确认可操作 | 375px 选城与预览 |

## 验收结果

2026-10-10 最终验收以代码基线 `7ef0ce6` 加本轮改动为准。真实模型长局不是此交互修改的验收依据，也不把历史真实模型结果作为本轮重测。

- **离线回归**：43 个测试文件，498 项通过；3 个实时测试文件默认跳过，其中 4 项实时测试未执行。新增 29 项覆盖草稿、副作用边界、输入排除、外交／路线限制、面板回填、余额和归属变化、待执行队列、共享 AI 请求计数、重复确认及底栏／弹窗位置。
- **构建与静态检查**：前端类型检查、前后端构建、4 项报告脚本测试通过；8 个改动的 TS/Vue 文件 Oxlint 0 错误、0 警告；`git diff --check` 通过。没有为本 PR 新建 GitHub Actions 工作流。
- **桌面浏览器**：1440×1000 的 Chromium 原生 WebGL 地图实际鼠标点选宜宾→昭通，进攻类型、源城、目标准确回填，选城阶段完整世界状态未变化。两种操作顺序、地图重选、列表回退、敌城拒绝、空白、拖动返回起点、A/M/Esc、输入控件排除、保存后真实读档清理与图层切换已检查。
- **实际调兵**：桌面和 375×812 触控模拟分别独立执行宜宾→泸州 1k；来源驻军 8→7、目标 8→9，行动点 6→5，银 1200→1198、粮 720→718.5。成功后同一未编辑草稿的确认禁用；不是用固定回执伪造执行成功。
- **忙碌与势力边界**：通过指挥面板发出请求并暂缓测试响应，实际观察两个地图按钮禁用、A 不进入模式；这是固定响应的网络忙碌测试，不是真实模型决策。额外触发 store 的势力选择动作验证草稿和面板关闭；真实读档路径使用保存／读取界面。
- **视觉与窄屏**：实际查看了出发城步骤、目标步骤、进攻预览、调兵预览及成功回执截图。首次窄屏确认按钮底部超过 812px，已修复为独立底栏；最终 375px 面板 x=12、宽 351，进攻确认和取消 y=709..741，面板底部 754，均在屏幕内。桌面最终面板 x=180、y=100、底部 950，确认底部 937，未遮挡顶部日期。长风险说明和目标列表仍可内部滚动，底栏不被截断。
- **标准游戏烟测**：运行两次技能提供的 `web_game_playwright_client.js` 并查看截图和文字状态；能渲染原生地图及择势界面。此默认烟测不含完整对局，新交互另由上述实际浏览器操作验收。

环境使用 Node 24.21.0 和锁文件依赖，没有更新依赖或存档格式。为了避免沙箱软件 WebGL 持续绘制占用 CPU，部分非动画交互检查暂停 Pixi ticker 并在截图前手动渲染；实际调兵时恢复 ticker。因此这轮不构成 WebGL 性能或流畅度达标证明。一次与浏览器并行的全量运行出现既有 AI 上下文用例 5 秒超时；关闭浏览器后保持原测试超时重跑，最终 498 项全部通过。新余额用例最初超额减银被现有 reducer 钳制，已改为正常小额事件耗尽余额，未修改经济规则。

可复现检查：

```sh
pnpm install --frozen-lockfile
pnpm --filter warlords-1931-web test:unit --run
pnpm typecheck
pnpm build
node --test scripts/report-tactical-pressure.test.mjs
```

浏览器复验：启动 `pnpm dev:web`，选择川军；分别从进攻／调兵按钮和已选宜宾进入，地图点昭通／泸州，检查预览并确认调兵。重复检查取消、地图重选、保存／读取、忙碌禁用及 375px 窄屏底栏。地图密集、小城难点时使用保留的下拉选择；这轮没有添加移动端缩放或新的城市命中规则。

## 保留的独立问题

本轮不修复已记录的“同批次先调兵再部署”初始驻军预检限制，也不承诺赤字恢复、AI 长期战术平衡或 WebGL 性能提升。原有大主包警告及 jsdom 未安装 Canvas 的提示需要单独处理。
