# 前线与补给：连接规则及占领整合

本轮让“能否到达目标”和“前线是否有补给”成为确定性的游戏规则，并增加可直接执行的前线预览面板。原有羊皮纸视觉风格、存档版本和自然语言指令保留。

## 已实现

- **连接图**：覆盖 375 个有效城市，979 条陆路连接来自地图的共同边界段，而不是城市质心距离或单点接触；另有 4 条显式游戏海路。完整游戏图连通，但某个势力的领土仍可能不连通。
- **路线**：从己方出发，中间只经过己方城市；敌方只能作为进攻终点，不能穿越敌方、盟友或第三方去打更远的城市。调兵的起终点和途经城市都必须属于己方，不能调到自身。
- **最低成本路径**：按路线逐段累计距离，海路段按 2 倍距离计成本；从合法路径中选择成本最低的一条。地图缩放、图层切换和模型提供的伪造 `route` 不会改变规则。
- **统一前置检查**：前线面板、玩家 AI、势力 AI 与执行层复用同一套可执行性检查。停战、同盟、驻军、行动点和银粮条件仍然生效，不合法路线在部署或扣款前拒绝；执行前再次检查最新归属。
- **实际支付**：预览和扣款使用同一条路径的成本。已有外出部队与新增部队一同计入参战和行军消耗，不再只为新增部队支付费用。
- **存档**：新战斗记录路径和计费距离，回放保留这些信息；旧战斗缺少路径时保留原来的距离回退，不强制重建历史路径。

## 轻量补给与占领整合

- **补给中心**：已整合、等级至少 3 的己方城市可供给前线。每个开局所属领土连通分区另指定一座区域补给中心，避免飞地与低等级势力开局就受罚；区域中心是可被争夺的城市基础设施，不与原势力永久绑定。
- **连接条件**：出发城沿己方城市连通任一已整合补给中心即为通畅，指定海路也可用于连接。盟友与敌方城市不能作为中转。失去连接后断供，重新连通即恢复。
- **断供后果**：仍允许进攻，但攻方确定性战斗公式中的有效战力乘以 0.8；与行军距离衰减叠加。并非直接把全部伤亡数字乘以 0.8，也不额外扣银粮或减少防守战力。
- **整合期**：新规则下战斗占城、协议割让城市后整合 2 回合，期间税收与粮食产出为 50%，养兵费用不打折；未整合城市不能成为补给中心，但允许己方部队经过。剩余回合按世界回合计数，不按一条指令或现实时间计。
- **透明反馈**：前线面板显示补给风险、目标整合期、预览银粮；执行结果显示本次实际支付费用，避免与后续指令的重新预览混淆。城市详情显示补给和整合状态，战斗日志记录当轮补给状态，占领日志显示整合期，AI 上下文读取同一规则配置。
- **兼容性**：新战斗带 `supplyRulesVersion: 1`，旧战斗没有此标记仍使用旧公式；旧占领事件未指定整合期，回放不追加新的惩罚。新的整合期限由占领事件与回合计数重建，存读档测试覆盖恢复过程。

当前系数在 `gameConfig.ts` 中集中维护。补给不是详细运输模拟，尚无铁路、海军控制、库存消耗、盟友通行协议或补给运输单位；战斗力与收益系数是首版可调参数，不是经长局验证的平衡结论。

以上为游戏规则与实现记录，代码见[map-war 项目](https://github.com/ZhengHaoF/map-war)中的 `campaignRoutes.ts`、`campaignPreview.ts`、`gameplayRules.ts` 和 `gameOrders.ts`。海路不代表真实历史交通、现行边界或可执行的现实路线。

## 使用方法

- 在地图工具栏点击“前线”，或点击己方城市、右键己方城市选择“行军预览”。
- 选择出发城、进攻或调兵、兵力与目标城；面板显示路线、银粮成本、可执行状态和拒绝原因。
- 进攻列表只列当前满足规则和资源要求的目标；也可从目标选择器查询其他目标为何不能执行。
- 进攻时“新增出兵”表示从驻军追加的兵力。若已经有外出部队，可以填 0，仅使用这些部队；调兵仍要求正数。
- “确认进攻”或“确认调兵”通过原调度器执行，消耗 1 回合行动点，不调用语言模型。合法进攻不等于一定能获胜，应同时考虑守军、工事、士气和兵力。

## 数据与再生成

陆路连接由 `scripts/build_city_connections.mjs` 离线生成：以 5 位小数规范化共同边界段，共同边界累计至少 100 米才建立连接。此方式依赖现有地图的边界分段一致性，不自动用最近邻弥补数据缺口。

显式海路在 `cityConnections.overrides.json` 中维护：舟山与宁波、海口与湛江、台湾与福州、三沙与海口。四条均为游戏设定；`excludeLand` 可记录复核后需要排除的陆路边。

```sh
node scripts/build_city_connections.mjs
node scripts/build_city_connections.mjs --check
pnpm --filter warlords-1931-web exec vitest run --pool=threads
```

生成结果包含原地图 SHA-256。测试会重新生成连接并与提交数据比较，也检查城市覆盖、边的唯一性与双向性、单点接触、短边界、缺失几何和显式海路规则。

## 验证范围与下一阶段

本轮覆盖合法出征、敌城阻断、跨海支付、己方调兵、预览与执行间的归属变化、停战与同盟、存档兼容等确定性场景。旧版实际模型返回仍可回放验证执行边界，但不等同于新规则下重新进行长局模型对战。

完整回归为 28 个测试文件、366 项测试通过，包含开局补给覆盖、断供与重新连接、补给城等待整合、税粮减半与养兵费用、空城占领、旧战斗兼容及存档回放。前后端构建、类型检查、ESLint 和连接图重生成校验通过；既有 Oxlint 问题和主包体积告警尚未处理。测试含此前收集的 6 条模型响应回放，并非重新调用模型验证新规则。

桌面与 375px 手机截图检查覆盖合法/非法行军、断供警告、补给城整合等待和完成后恢复。合法出征实际反馈为银 2.5、粮 1.9，行动点由 6 变 5，符合该预览；未观察到页面脚本错误。沙箱中原生指针及键盘确认未可靠触发部分按钮，部分执行检查使用 DOM 点击事件并核对界面和真实状态，因此不把这些检查称为完整的真实输入兼容性验证。

下一阶段用 20 至 40 回合可复现模拟检查经济、扩张成本和 AI 节奏，再调整系数及阶段目标。本轮未宣称长局平衡完成；常规动画异常的完整事务回滚仍需独立加固，海路倍率也需实际试玩调参。
