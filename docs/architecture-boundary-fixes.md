# 架构边界修复说明

本次优先修复上一轮评估中能影响游戏结果、存档完整性及模型代理安全的边界问题，保持现有 Vue / Pinia / NestJS 技术栈，不做全量框架重写。调度引擎由 Claude Opus 5.5 辅助深审，最终代码仍需经过真实 store、调度器及编排器的离线回归验证。

## 世界态提交与演出

- **同步批量提交**：`store.applyEvents` 为资源扣款、行动点与领域效果提供同一提交边界。批内任一事件失败，恢复批前状态和事件日志；提交中抑制自动存档及提示。
- **付费指令**：征兵、建设、筑防、整军、行军、派兵、开战和撤退先验证并提交，再尝试视觉演出。动画失败不退款、不回滚已经生效的动作，也不会让前线只扣钱却没有开战。
- **防御性复制**：快照的关系对象和战斗路线数组不再引用可变世界态；提交事件也复制入库，避免调用者在提交后改写历史。
- **兵力约束**：移动兵力必须有限、正数、来源足够且不是同城移动。不能通过超额移动凭空增加目标兵力。

这不是完整的独立纯领域引擎。`gameOrders.ts` 仍包含演出和历史测试 mock 的兼容路径，后续应提取领域 command handler，并让测试更多使用真实 store。

## 外交提交

- **双方同意**：AI 对 AI 的结盟与停战不再把“提案”直接当“接受”。当前接收方使用明确的本地规则：例如共同敌人条件下接受结盟，停战根据关系及兵力条件判断。
- **停战期**：声明战争及协商执行均先检查停战保护，不先扣费再拒绝关系变化。
- **整批预算**：银粮条款累加检查，割城校验归属与重复项，援助校验目标和规模。条件、费用、援助与关系变化一起提交，不能先兑现收益再发现后续条件失败。
- **旧回复失效**：读档、换势力、取消或开始新谈判会作废旧会话，并中止相应请求；回复落地前再次校验世界代次与协商身份。
- **失败记录**：无法履约的已归档条约标记拒绝，并使用明确的失败叙事，不再保留误导性的“已接受”结果。

外交接受策略是保守的第一版，未实现接收方单独调用模型进行多轮谈判。条款结构也仍以玩家偿付为主，后续要扩展为明确的付款方、收款方和互惠交易。

## 存档与重放

- **先验证后重建**：存档 JSON、事件类型和结构、嵌套经济数据、日期及关键元数据先验证。结构损坏不能替换当前游戏。
- **失败恢复**：重放过程中出现异常时恢复旧世界及旧日志。重放标志在 store 内部复位，不依赖地图组件是否挂载。
- **暂停快照**：通过 `useSaveGame` 手动保存时附带暂停回合的阶段、剩余指令及执行上下文；读档后经形状、世界锚点和权限校验恢复，执行时再次检查实时游戏规则。
- **旧存档兼容**：没有暂停快照的历史存档只能依靠事件日志恢复已收税、未推进日期的半回合；无法恢复从未落日志的剩余 AI 指令，不能假装这些指令仍在。

编排器向 store 注入只读快照提供器，因此直接调用 `store.save` 的自动存档及外交存档也能保存已暂停的回合，store 不反向运行时依赖 kernel。已开始结算的回合不导出半成品快照；旧存档或明确不附带快照的存档仍走日志兜底。

## AI 调度引擎

重点审查内容包括编排器与调度器的状态机交接、暂停与失败断点、经济和日期的幂等性、世界代次及异步写回、战斗裁决边界，以及模型重试和后端取消。详细结论见同目录 `ai-scheduler-review.md`。

总体方向正确：AI 提出有限指令，规则层控制权限和资源，战斗基础公式决定结果，模型只在允许范围内调味。主要问题原来是编排器把调度器的“暂停”和“完成”混为一谈，缺少持久化运行时断点；本次改为显式阶段与暂停会话。

后续已增加整轮战斗原子事务：任何战果事件失败都回滚整轮，提交成功后才标记已结算并播放演出。另修复旧战线重复占领已易主空城的问题，因此部分未来战果会与旧版不同；基础公式和补给参数未调。详见 `battle-atomic-settlement.md`。

## 后端代理与生产部署

详见 `ai-proxy-security.md`。新增生产认证失败关闭、模型与请求字段白名单、输入和输出预算、限流、并发与排队上限、显式上游超时和重试策略，以及浏览器断开到上游的取消传播。

这不是一次生产部署。部署方需要配置可信反向代理认证、服务端共享秘密和后端网络隔离；不能把共享秘密放进前端，也不能只设置秘密而省略用户认证。多实例部署还需要网关或共享存储上的全局限流。
