# map-war 敌方主动目标与游戏性复评

本轮为[map-war 项目](https://github.com/ZhengHaoF/map-war)加入前线优先目标、事件时归属记忆及预检失败回执。小样本已出现实际增援、主动收复作战及战中部署，但完整真实模型长局尚未完成，不能据此宣布平衡或长期耐玩性已经解决。

## 实现内容

- **公开局势建议**：先防守受攻城市，再支援已有战线、提示恢复断供，比较近期六回合失地的收复、集结、占领整合及可达交战目标。没有强制执行、免费资源、额外行动点或对和平势力强制宣战。
- **行动例子**：使用正常路线与执行边界检查，保留至少 2k 或四分之一来源驻军。建议中的兵力比例只是粗略阈值，不是胜率；每条例子分别合法不等于整批预算已经批准。
- **失地记忆**：按事件发生时的城主筛选势力历史，原城主失地后仍能看见易主；损失改用“攻损/守损”，避免守方把攻方损失当成自己的损失。
- **未执行反馈**：结构和战略预检拒绝生成可信、零费用回执，保留原因与当时余额。后续提示强调当前预算，而不是复制历史余额；成功行动仍走正常队列与扣费。
- **字段说明**：真实回复出现内政误用 `from` 后，补充“内政用 `gb`、来源城用 `from`”。此补充通过自动检查，但其减少真实模型错误的效果尚未验证。

## 真实模型短样本

模型为 `step-5-preview`。川系使用固定控制策略，滇系调用真实模型；正常 375 城市经济、路线、费用、行动点、战斗与日期推进保留，其他势力等待，无外交结算，演出与战斗修辞使用替身。因此这是实际模型加规则引擎压力测试，不是完整浏览器真人对局，也不是两个模型相互对战。

| 样本 | 有效模型决策回合 | 规划指令 | 预检拒绝 | 实际执行 | 执行层拒绝 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首轮防守 | 5 | 19 | 0 | 19 | 0 |
| 首轮失地后反攻 | 2 | 3 | 0 | 3 | 0 |
| 重新开始的防守短段 | 3 | 11 | 3 | 8 | 0 |
| 重新开始的反攻短段 | 2 | 2 | 0 | 2 | 0 |
| 合计 | 12 | 35 | 3 | 32 | 0 |

这里的“12”是四段短样本合计，绝不是连续十二回合对局。后三条预检拒绝不是执行失败：模型把 `recruit/rally/fortify` 的目标城市写成 `from`，缺少必须的 `gb`；系统记录了三个零消耗失败回执，没有自动猜测并执行。

- **防守响应**：首轮滇系从昆明向昭通调兵、征兵、整军和筑防；五个有效回合结束时仍保有昭通，驻军 24k、工事 50、士气 83。重复开始的三回合段同样保有昭通，但第三回合出现上述字段错误。
- **反攻响应**：反攻场景先由正常战斗引擎完成川系开局占领，滇系仅在该场景设置阶段等待，没有直接写入假占领。随后滇系从昆明新增出兵 13.5k 进攻昭通，下一回合实际部署援军；两个有效规划回合结束时昭通仍属川系，不能把“已经发起反攻”写成“已验证持续成功收复”。
- **实际费用**：上述 32 条已执行行动共消耗 32 点行动点、422.9 万银及 266 万石粮。三个结构拒绝零消耗；执行层零拒绝是在预检过滤之后的样本结果，不代表模型无效指令率为零。
- **受挫调整**：后续上下文已包含真实失败原因，且自动测试检查其保存加载一致性。但下一回合规划未成功返回，不能声称模型已经根据失败反馈改正。

## 长测中断与记录口径

原计划每个场景十二回合，但没有完成两场完整长局。首轮旧测试把请求失败当成空行动继续推进，生成了不适合作为有效模型对局的后半段；报告只采用请求成功且解析成功的前五及前两回合，不使用后续胜负或任务完成状态证明策略能力。

测试器现改为请求最终失败即暂停，不再推进日期；正常存档形成检查点，续测时先校验恢复状态与此前快照完全一致，再重新规划。一次分段运行仍遭遇执行器超时，之后新会话续测的两个场景均在三次重试后收到上游 502，保持原检查点；长局未通过，不能归类为完整验收成功。

客户端保存的 45 次请求包括 12 次 HTTP 200、17 次测试代理会话失效的 HTTP 401、16 次上游 HTTP 502。代理日志另外保留一条执行器中断期间未形成完整客户端记录的 502，总计 46 次；该未完成请求不计有效模型回合。所有失败与重试均保留，未只留下最终成功响应，记录不含密钥、请求头或模型私有推理。

原始客户端记录为 `map-war-pr7-pressure-defense-initial.json`、`map-war-pr7-pressure-counterattack-initial.json` 和 `map-war-pr7-pressure-resumed.json`，代理记录为 `map-war-pr7-provider-calls.jsonl`。这些是本次工作区的测试证据，不是部署后会持续运行的监控服务。

## 浏览器与工程验证

- **原生输入**：正常填写将领名、选择川系、发送开局命令、结束回合、展开其他势力摘要、滚动及点击“知道了”。首次滇系响应来自真实模型的录制返回，玩家和其他调用固定；这是离线响应重放，不增加真实模型样本。
- **可见反馈**：昭通首回合未被攻下，摘要显示本方战损与收支，展开区显示滇系例行变化 5 项。该数字是事件聚合数，不是五条模型指令；实际录制回复包含四条指令。
- **尺寸与视觉**：桌面 1440×1000、窄屏 375×812 已取图检查。通知消退后摘要清晰，滚动区与固定继续按钮正常；窄屏摘要主体横向范围 13–362，文档宽度 375，没有新增横向溢出。未把可滚动内容超出可视区误判为所有行同时可见。
- **渲染边界**：显式使用现有 Canvas 降级渲染。持久浏览器工具受长执行任务阻塞后使用有时限的原生 Playwright 脚本完成流程，浏览器已关闭、无页面错误；这不是用户设备 GPU 或帧率基准。
- **自动回归**：38 个测试文件、438 项通过；独立联网压力测试默认两项跳过。十四项新增专项覆盖目标、守军、外交、断供、预算、失地记忆、失败回执及存读档；类型检查、前后端构建通过。
- **静态检查**：JavaScript ESLint 通过，八个相关新增/改动文件 Oxlint 无错误；全项目仍有 41 条既有 Oxlint 错误。主包约 798.10 kB、gzip 236.16 kB 的体积警告仍在。
- **通用游戏助手**：三十秒有界运行退出 124，虽然写出了起始截图和可读状态，但未完成流程，不列为通过项。它的截图已检查，不用旧的黑屏结论替代本次实际观察。
- **预览范围**：静态预览只更新前端，没有部署隔离测试代理或密钥。真实模型玩法仍需要游戏后端，不能把前端预览当成已接通模型的完整游戏服务。

## 游戏性判断与下一步

**本轮的有效改善是“对手会针对玩家行动作出回应”，不是“AI 已经成熟”。** 昭通不再只能靠玩家单方面推进；调兵和筑防确实增加攻城成本，失地后的主动开战让驻守和增援有了必要。相较仅增加叙事文字，这些是规则层真实发生的交互。

目前仍存在明显边界：防守可趋向重复调兵和筑防，进攻建议用粗略兵力阈值而非完整战力比较；战损、城防、士气、补给和反攻所需时间是否能在三回合守住任务内形成足够压力，尚未完成有效长局验证。调用等待与失败也影响回合节奏，省略内政动画并不解决模型等待时间。

- **下一开发优先级**：补充可解释的战术比较，区分“现在进攻、继续集结、保守驻守、支援或撤退”的成本与风险，并利用可信失败记录避免相同计划反复失败。保持现有费用与动作边界，不以免费兵力或强制战斗制造难度。
- **下一验证优先级**：在请求稳定的环境中按单场景、小分段正常存档续测十至十五个有效回合，检查持续防守、反攻机会、补给争夺和失败后改正。明确暂停与失败状态，只有全部段落完成才写长局通过。
- **暂缓扩大内容**：先验证现有昭通、宜宾目标的取舍与压力，再扩展新战役、科技树或复杂运输。没有长局证据前，不凭两个开局样本调整全国经济系数或承诺胜率。
