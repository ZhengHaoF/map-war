## 试玩方法

- **实际界面**：川军开局，通过输入框、地图点选、预览确认、键盘激活按钮进行操作。状态钩子只读，不修改 store 或制造战果；未停止 Pixi ticker 或替换游戏动画。
- **模型与认证**：沿用已授权凭据的 `step-5-preview`，使用隔离测试转发层；真实前端、规则、调度器和 reducer 保持不变。这不是 NestJS SDK 认证配置验收。
- **环境边界**：沙箱 Chromium 的软件 WebGL 下约 0–1 FPS，普通定位器动作多次超时；改用 DOM 读取控件位置后的原生指针，以及聚焦控件后的原生键盘输入。截图已另行核对，不据此推断用户 GPU 设备也只有这个帧率。
- **样本边界**：短局体验，不是完整通关、长期赤字修复或十至十五回合连续敌方压力验证。连通性探针、转发会话失败与游戏指令分开统计。

## 已确认的问题

### 模型失败后，回合缺少明确的降级标记

测试转发会话到期时，滇系决策、次要势力批量决策、战斗调味与世界叙事四个请求返回 401，错误为 `invalid or expired session token`。这是测试连接状态，不是用户额度结论，也不是模型主动选择按兵不动。

实际游戏仍完成默认战斗结算、占领、摘要和日期推进，摘要看起来与普通成功回合一致，未明确列出哪些 AI 决策没有取得有效回复。代码中政权与批量请求的 rejected 结果被跳过，世界叙事失败落默认文字；因此玩家可能误把“敌方决策缺失”理解为“敌方选择不行动”。

建议保留可继续游戏的降级机制，但让回合摘要持久标注请求状态、缺失势力与默认结算，提示重试语义，不能只显示普通的“回合结束”。这不要求把已落地的经济和战斗重复执行。

刷新后，滇系又连续三次返回上游 `502 / upstream request failed`，世界批量、调味和叙事却正常。因此这项问题不只由首次测试连接失效触发。本轮日期和行动点实际正常推进，未复现“日期不推进”或重复经济结算，不能把等待中的临时状态当作最终故障。

### 读档恢复了世界，却没有恢复对话边界

复现：4 月 15 日保存基线（宜宾 10k、6 行动点）→发送“仅在宜宾征兵 1k”→真实执行成功（11k、5 点）→通过读取界面恢复基线。实际世界、银粮、战线和事件全部恢复一致，但指挥面板仍显示存档之后的“宜宾就地募丁，得壮士千人”“recruit ✓”“已执行 1 条”。

这不是读档后又扣了一次费用，而是 UI 成功记录与当前世界脱节。`PlayerAiPanel` 的 `chatHistory` 没有在读档时清理，`onSend` 仍会取最近五轮注入下一次 AI 对话；可能把已被读档撤销的行动当作当前世界的既成事实。没有进一步编造一次错误执行来证明潜在影响。

建议读档时明确清理或按存档事件重建聊天、建议与待执行草稿，并检查加载期间未完成的异步请求是否应作废。本轮只报告并保留证据，尚未实施该修复。

### 单个敌方请求长时间拖住世界回合

滇系三次失败请求的返回耗时分别约 100.4、100.4、93.3 秒，累计响应等待 294.2 秒；同一轮世界批量请求约 76.9 秒即已成功，却仍须等待该敌方的重试流程。首个世界决策请求发出到结算叙事返回的跨度约 365.5 秒，包含并发等待、退避和中间执行，不是单个服务响应时间，也不包含最后日期演出。

当前界面主要显示“政权 AI 决策中…”，没有逐势力的成功／失败／重试信息和可取消等待入口。建议为每轮设置明确截止策略与可见进度，并与降级标记一起设计；不据此承诺所有用户都遭遇相同延迟。
