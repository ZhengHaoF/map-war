# 地图进攻／调兵：先动作、再两次选城

本轮按用户截图中的交互纠正实施，以 `240d503` 为代码基线。最新要求覆盖[最初的地图选城方案](https://github.com/ZhengHaoF/map-war/blob/master/docs/map-command-shortcuts-implementation.md)中“已有选中城就跳过第一步”“弹窗内地图重选”和绿色候选的旧设计；旧报告只作历史记录。

## 交互与实现

- **闲置点击**：直接点击己方城市仅选择地图区域，不再弹出行军预览。右键城市信息仍保留，但移除信息面板与右键菜单里的直接预览入口。
- **第一步**：点击工具栏“进攻”或“调兵”，始终清空上一组城市并从出发城开始。己方城市黄色高亮，显示“请选择进攻城市”或“请选择调兵城市”及 `1 / 2`；即使之前点过己方城市也不跳步。
- **第二步**：点击合法己方出发城后，显示“请选择进攻目标城市”或“请选择调兵目标城市”及 `2 / 2`、出发城名称。可选目标黄色、出发城蓝色；非法点击保留阶段并解释原因。
- **两城完成**：选中合法目标后，才打开原有行军弹窗并一次性带入行动类型、来源和目标。保留弹窗里的下拉调整、兵量、路线、费用、风险及最终确认。
- **入口收敛**：移除截图中两个“地图重选”按钮、选城期间“用下拉选择”的提前弹窗入口；“前线”入口也从第一步进攻选城开始。目标阶段提供“重选出发城”，重新选择两城。
- **取消与异步**：取消／Esc 清理两城、错误、高亮和预览。切换进攻／调兵重启第一步；切图层、读档、回放或势力变化继续取消草稿。自动切到市级地图后用序号检查已取消或被替换的选择，避免旧回调重画提示。
- **执行边界**：地图选城不入队、不扣费、不发兵、不推进日期。只有预览底栏的最终确认走既有调度器和规则复检；高亮仅表示当前阶段的归属、路线和外交条件，不保证预算充足或攻击安全。
- **颜色与布局**：候选颜色统一为 `#f6cc38`，加强黄色填充及深黄色边框。新增独立 `MapCommandPicker`，桌面提示放右上，窄屏放底部，不改变既有羊皮纸风格。

高级推理模型 GPT 6.1 Sol 直接完成实现与验收，没有委派低阶模型。没有变更费用、战斗、经济、存档结构、依赖或模型配置。

## 原生浏览器验收

使用本地开发构建、真实 Chromium WebGL 地图及原生鼠标／键盘输入。只读状态钩子用于核对，不直接调用选城方法、不注入世界状态、不伪造成功回执，也未暂停 Pixi ticker。

- **进攻链路**：闲置点击宜宾不弹窗；再点进攻仍从第一步开始。选宜宾后显示第二步、15 个合法目标，未开预览；误点己方成都被拒绝；选昭通后才开弹窗，类型 `battle`、来源宜宾、目标昭通准确。整个选择及取消过程日期、兵力、行动点、银粮和事件未变化。
- **调兵链路**：调兵始终从第一步开始。选成都后不开弹窗；误点敌方昭通被拒绝；选宜宾后带入 `moveTroops` 和正确两城，尚未扣费。
- **实际确认**：通过该两步地图路径执行成都→宜宾 1k。成都驻军 `150→149`，宜宾 `8→9`；行动点 `6→5`；银 `1200→1194.5`，粮 `720→715.9`，与预览银 `5.5`、粮 `4.1` 一致。只有一条成功回执；日期仍为 `1931-04-01`、回合 0，没有新战斗。
- **探索边界**：目标阶段切换操作清空两城；敌城不能作出发城；“重选出发城”回到第一步；A 与 Esc 快捷键、调兵按钮、两个阶段取消、“前线”入口及切到省级取消已检查。地图拖动、滚轮缩放未被当作选城，预览期间地图点击没有改写已选两城。
- **读档**：用实际保存／读取界面建立存档，在第二步目标选择期间读取。两步草稿、候选高亮、错误和弹窗均清理；日期、预算、两城兵力与成功回执恢复到保存时状态。保存的 JSON 会正常省略事件中值为 `undefined` 的可选字段，因此证据比较按 JSON 语义归一化，不将字段省略误报为世界变化。
- **证据**：22 个浏览器检查及只读状态写入[脱敏验收记录](https://github.com/ZhengHaoF/map-war/blob/master/docs/fixtures/map-command-two-step-browser.json)。没有观察到 `pageerror`；最后取消后成功回执仍只有一条。截图另随结果提供，不包含账号凭证或外部模型回复。

桌面截图已检查：第一步黄色己方候选、第二步黄色目标及蓝色来源、非法点击说明和最终预填进攻弹窗均可见。375×812 窄屏也用原生滚轮放大及地图点击完成宜宾→昭通两步并检查截图；两步提示、黄色目标、蓝色来源、取消／重选与预填弹窗可见。窄屏提示宽 351px，弹窗位于 `12,12`、尺寸 `351×742`，底栏 `y=696..753`；页面宽 375px，没有新增横向溢出，确认／取消未被截出视口。窄屏调兵选成都后取消，资源和事件保持不变。

地图地名密集时仍需缩放或平移，不新增自动避让或命中算法。这里是 375px 浏览器视口的鼠标／键盘验证，不是实体手机或触屏设备的兼容性结论；沙箱软件 WebGL 仅 0–1 FPS，不作为性能达标证明。

## 复验与范围

```sh
pnpm --filter warlords-1931-web exec vitest run
pnpm build
node --test scripts/report-tactical-pressure.test.mjs
```

启动开发服务器后选择川军，依次试“进攻→宜宾→昭通”和“调兵→成都→宜宾”，确认必须点完两座城市才弹窗。调兵最后确认前后核对资源，重复试取消、重选、动作切换及 375px 视口。

本轮是地图交互修正，不是新的真实模型连续对局，也没有调用外部决策模型。独立的世界回合截止、逐势力重试进度、取消等待和 WebGL 性能工作未纳入本轮；静态预览不附带模型后端。
