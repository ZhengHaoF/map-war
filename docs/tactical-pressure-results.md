# map-war 十二回合真实模型续测与游戏性复评

本轮在 [PR #8](https://github.com/ZhengHaoF/map-war/pull/8) 的战术提示版本 `80442f2` 上，完成同一反攻场景的十二个有效模型决策回合。第一回合来自上一轮，内容核对完全一致；本轮新增十一回合，通过正常存档续测，不拼接不同开局。对手在这条样本中形成了“反攻、持续增援、收复、整备、再扩张、守住反扑”的过程，但不能据一局判断全国平衡或提示的因果效果。

## 方法与覆盖

- **真实部分**：`step-5-preview` 规划滇系，正常结构和战略预检、执行、费用、375 城市经济、战斗及日期推进。十二次有效响应均成功解析并形成指令，十二段有效决策之间日期每次前进七天、世界回合每次增加一。
- **控制部分**：固定川系策略，开局征兵与进攻昭通，通过正常战斗占领；准备阶段滇系等待，之后使用真实模型。川系占昭通时持续征兵 2 与筑防最多 5，失地后宜宾征兵/再攻并支援；其他势力等待，无外交结算，演出、战斗修辞和提示展示替身。
- **分段续测**：读取正常存档，测试比较恢复后的日期、目标、两方余额、两城状态和活动战线与此前记录一致。请求失败不会推进为有效回合，未完成回合的川系动作及经济变化不进入下一段保存结果；恢复后重做该回合。
- **不是原生浏览器长局**：这次为规则引擎联网测试，不能替代真人操作体验、全势力对战、真实设备性能或含外交和战斗修辞的完整对局。前轮桌面/窄屏浏览器验证仍单列。
- **覆盖边界**：反攻场景 `12/12, complete=true`；防守开局场景本轮未运行，不能称两场长局都已完成。

## 游戏性判断

- **敌方压力确实存在**：连续五次部署支援反攻战线，之后把资源投入新占城，再在川系反扑时加强防守；不是只发宣言或例行远地内政。昭通与泸州的易主让地图局势改变，这条局部循环已具有比单次出兵更明确的后果。
- **建议不是答案**：第一和第八决策都没有采纳先集结，模型选择合法开战，之后都在本样本内取得目标。不能仅因基础攻损大于守损就认定应撤退，也不能因为最终成功就证明初始冒险必然合理；后续增援、双方整军、守方士气及崩溃判定影响结果。
- **士气取舍比纯堆兵更重要**：川系固定征兵与筑防，昭通兵力仍增长但士气持续下降，最终崩溃；滇系后来主动整军。这提示下一步应让双方士气风险更容易解释，而非把基础损耗提示包装为完整胜率。
- **存在重复但未证实无效**：后半局反复征兵、筑防、整军和调兵，其间防守兵力、工事与士气确有增加，不应把合法重复直接统计为无效指令。但本局仍偏向固定每轮补充，缺少多种控制策略对照，尚不能证明长期玩法多样。
- **经济压力未验证**：滇系结束时银 963.5、粮 2147.6，川系银 1200.1、粮 3139.6，均未破产。调兵量从 5k 改为 3k、1k 可观察，但没有预算拒绝，不能称其为已验证的预算受挫学习。
- **撤退与失败调整未覆盖**：撤退指令为 0，预算/路线/外交等预检或执行拒绝也为 0。本次仅验证了公开失地后的持续应对，不能宣称所有分类受挫分支已成熟；服务重试不是游戏策略调整。

## 发现的工程风险：读档后复用历史战斗编号

续测还发现需要优先修复的既有问题：`nextBattleId()` 只扫描当前 `store.battles`，结束的战线已从列表删除；正常读档将运行计数器清零，因此所有旧战线结束后新建战线会复用历史编号。本局最初宜宾进攻与后来的昭通进攻泸州都使用 `battle_1`，旧昆明反攻与新的宜宾反攻都使用 `battle_2`；活动战线编号没有同时冲突，但历史编号并不唯一。

这会影响以战斗编号关联的历史解释，并且崩溃判定的种子包含编号，故“恢复的当前快照一致”不等于“读档与不中断运行的未来结算必然一致”。十二回合是正常存档链上的实测结果，而不是已证明与不读档长局等价的结果；两次崩溃也不能被归因于新风险提示。测试期间未修改规则或编号算法来取得结果，此问题留待专项修复与前后对照，不混写为已修复。

## 请求与复现边界

完整记录含 24 次客户端请求：12 次 HTTP 200、11 次 HTTP 502、1 次 HTTP 401。第一回合的成功调用来自上一轮，本轮桥接日志为新增 23 次请求；成功调用耗时中位数约 78.9 秒，不含失败重试，也不是浏览器端整回合响应时间。

401 的返回消息为测试连接会话令牌无效或过期；刷新同一已批准连接后可继续，没有证据表明用户服务额度耗尽。502 仅可确认返回上游请求失败，不能据此推断计费、余额或具体故障源。失败尝试和恢复单列，最后有效记录为世界回合 13、1931-07-01。

`scripts/report-tactical-pressure.mjs` 校验单场景连续编号、每次七天日期推进、每次世界回合加一、有效解析和成功响应数量，生成 CSV 与脱敏 JSON。公开证据保留建议、指令、回执、两城/余额/战线快照及军事事件，不包含完整存档、密钥、请求提示或私有推理；私有原始记录与正常续测存档单独保留。脱敏摘要不是可以单独复现整局的完整存档或所有模型输入输出集合。

本次生成结果保存在 `docs/tactical-pressure-12turn.csv` 与 `docs/fixtures/tactical-pressure-12turn.json`。脚本现在显式接受“此前已完成的有效决策数”和玩法代码提交号，新开局默认此前计数为 0，不再自动扣除一回合或冒用旧代码提交号。下面的 `1` 只适用于本次已有一回合的历史样本；缺少提交号时报告会保留 null，不伪造版本。

```sh
node scripts/report-tactical-pressure.mjs /path/to/private-pressure.json /path/to/output-prefix 1 80442f28cbf07ab595c7dfe7b1a9af1277b87897
```

## 下一优先级

- **先修存档语义**：从事件历史恢复已使用的最大战斗编号，补充“结束战线后读档再开战”及“读档/不读档后续编号与崩溃种子一致”回归；旧存档和既有战斗结果不回写。
- **再改善解释**：风险文本同时解释攻守士气区间，避免“需要权衡”后紧接“当前相对有利”的措辞混淆；不要自动预测必然崩溃或限制合法进攻。
- **补受挫覆盖**：用正常合法行动形成资源紧张、进攻不利等独立场景，检查下一决策是否减少批次、保存兵力或撤退；不把本局零拒绝代替这些验证。
- **再评目标节奏**：比较只征兵/筑防和加入整军的川系策略，检查三个回合目标是否过早给出胜利感。先拿对照数据，再决定要不要增加“完成后守住”挑战或调参数，不立即改变已完成记录语义。
